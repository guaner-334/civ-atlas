# 插件包

插件就是一个 `.civplugin` 文件。读写和检查的代码在 [`src/plugin/pluginFile.ts`](../../src/plugin/pluginFile.ts),网站和服务器用的是同一份。

## 文件里有什么

`.civplugin` 是一个**不压缩**的 ZIP,里面只能有下面这几个文件,多一个、少一个都不认:

| 文件 | 必须 | 最大 | 说明 |
|---|---|---|---|
| `manifest.json` | 是 | 64 KB | 清单,UTF-8 的 JSON,字段见下面;打包时生成 |
| `main.js` | 是 | 1 MB | 插件代码,只能有这一个 JS 文件;UTF-8 的文字 |
| `README.md` | 是 | 64 KB | 说明,装的时候当纯文字显示 |
| `LICENSE` | 是 | 64 KB | 许可证全文 |
| `icon.png` | 否 | 64 KB | 图标,128×128 的 PNG |

整个文件最大 2 MB。`main.js` 要是人能读的代码:不压缩、不混淆,别人装之前能打开看(作品墙审核时也要看)。用到的库直接写进这个文件。

**插件的指纹 = 整个文件字节的 SHA-256。** 世界里记下用过哪个插件、作品墙上审过的是哪一版,都按这个指纹认:改一个字节就是另一个插件文件。所以文件要原样存、原样传,别解开再重新压缩。

## 清单

`manifest.json` 里的字段。「打包填」的几项由打包工具写,自己写的放在文件夹里的 `plugin.json`(见下面「打包」)。

| 字段 | 谁写 | 规矩 |
|---|---|---|
| `app` | 打包填 | 固定 `"文明与地图"` |
| `kind` | 打包填 | 固定 `"plugin"` |
| `format` | 打包填 | 外壳和清单的版本,现在是 `1` |
| `id` | 你 | 插件编号:小写字母开头,只有小写字母、数字,中间可以有单个 `-`;最长 32 个字。世界里存插件的数据按它起名,发布以后别改 |
| `name` | 你 | 给人看的名字,最长 40 个字 |
| `version` | 你 | 第几版,`主.次.补丁`,比如 `1.2.0` |
| `role` | 你 | 插件种类,现在只有 `"tool"`(工具) |
| `api` | 你 | 用第几版接口,现在是 `1` |
| `runtime` | 你 | 跑法,现在只有 `"worker"`(在后台线程里跑) |
| `requires` | 你 | 要的能力,`"名字@版本"` 的数组,比如 `["world.read@1", "layer.cells@1"]`;网站没有其中任何一样就装不了 |
| `optional` | 你 | 可选:有就用、没有也能跑的能力。网站没有的不给,插件照样装 |
| `why` | 你 | 可选:能力 → 为什么要它(最长 100 个字),显示在权限框那一行下面。只能写 `requires`、`optional` 里有的能力 |
| `entry` | 打包填 | 固定 `"main.js"` |
| `files` | 打包填 | 清单以外每个文件的路径、SHA-256、字节数 |
| `description` | 你 | 可选:一句话说明,最长 200 个字 |
| `license` | 你 | 许可证的名字,SPDX 写法:`MIT`、`Apache-2.0`、`GPL-3.0-or-later`…… |
| `author` | 你 | 可选:`{ "name": "…" }`,只用来显示,最长 40 个字 |

另外:

- `requires` 和 `optional` 加起来最多 32 项,同一样能力不能写两遍(两边都写也算)
- 给人看的字(`name`、`description`、`why`、`author.name`)不能空着,不能有控制字符和改写显示方向的字符
- 这一版网站认不出的字段不管;清单的结构最多套 8 层,不许用 `__proto__`、`constructor`、`prototype` 当键
- 有哪些能力、各对应权限框上哪一行,见[能力、权限和限制](limits.md)

### 装不上时怎么说

网站读插件文件出错分两种:

- **坏了**:格式不对、缺文件、多了文件、文件和清单记的对不上、字段不合规矩……插件文件本身有问题,会说哪里不对
- **要更新网站才能用**:文件是好的,但用了这一版网站还没有的东西:`format`、`api` 比网站新,`kind`、`role`、`runtime` 不认得,或者 `requires` 里有网站还没有的能力(`optional` 里的不算)

## 打包

插件文件夹里放:

```
my-plugin/
├── plugin.json   清单里你写的那几项(上表「你」那一栏),打包时补上 app、kind、format、entry、files
├── main.js
├── README.md
├── LICENSE
└── icon.png      可选
```

别的文件(测试、草稿、编辑器配置)打包时不管。在这个仓库里:

```bash
npx tsx scripts/pack-plugin.ts path/to/my-plugin                  # 写出 path/to/my-plugin/<id>.civplugin
npx tsx scripts/pack-plugin.ts path/to/my-plugin out.civplugin    # 写到别处
```

打包先照网站读插件的规矩核对一遍,不合格的直接说哪里不对。同样的内容每次打出来的字节一样,指纹也一样。

## 版本和兼容

- **插件自己的版本**(`version`):改了就加。装了的插件不自动更新,用的人再从文件装一次新版才换;新版要的能力比旧版多,会再问一次
- **接口的大版本**(`api`):整套接口一个大版本,现在是 1
- **每样能力单独带版本**(`world.read@1` 里的 `@1`):给一样能力加新的调用、给调用加可选的参数或返回的字段,都不算改版,版本号不变;某样能力的意思变了,出它的第 2 版(`world.read@2`),第 1 版还会留一段时间,让插件有时间跟上
- 网站不认得插件要的能力(比如插件比网站新),装的时候说「要更新网站才能用」,不会装上以后才出错

## 许可证

- `license` 写许可证的名字,`LICENSE` 放全文,两样都必须有
- 作品墙开始收插件以后,上架的插件要用开源许可证(用哪种你自己选),别人才能放心看代码、装来用
- 这个仓库里的示例插件和这份文档都是 MIT,可以直接拷去改
