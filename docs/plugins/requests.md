# 缺接口怎么办

想做的事现有接口做不到,就把它提成一条**接口需求**。接口是照大家实际想做的插件一批批加的:说清你想做什么、卡在哪,比等它自己出现快得多。

用 AI 帮你写插件的,让它先读这一页最后的[给 AI 助手](#给-ai-助手)。

## 先确认真的做不到

1. **查文档。** 工具插件看[接口参考](api.md),推演插件看[推演插件](sim.md),地图插件看[地图插件](map.md);各种上限和沙箱挡住的事在[能力、权限和限制](limits.md)
2. **看看是不是该换一种插件。**

   | 想做的 | 用哪种 |
   |---|---|
   | 量一量、算一算、加图层和标注、替用的人改名加标记下命令 | 工具插件 |
   | 让历史走得不一样:加自己的数、影响官方的决定、下命令、写编年史 | 推演插件 |
   | 让地图长得不一样:改海拔、改气候 | 地图插件 |

3. **搜一下有没有人提过。** 在 [issue 里搜「插件接口需求」](https://github.com/guaner-334/civ-atlas/issues?q=is%3Aissue%20%22%E6%8F%92%E4%BB%B6%E6%8E%A5%E5%8F%A3%E9%9C%80%E6%B1%82%22)加你的关键词(开着的、关了的都看)。已经有同一件事的,在那条下面点 👍、补一句你想拿它做什么,不另开新的

[能力、权限和限制](limits.md)里「插件做不到的事」那几样(联网、调 AI……)是沙箱挡住的。真有非它不可的用途也可以提,写清要连哪里、拿来做什么。

## 怎么提

三条路,写的内容一样:

- **网页**:[新建 issue](https://github.com/guaner-334/civ-atlas/issues/new?template=plugin-interface.yml),选「插件接口需求」,照表单填
- **命令行**:照下面的格式写成一个文件,比如 `request.md`,再

  ```bash
  gh issue create --repo guaner-334/civ-atlas --title "插件接口需求:<一句话说缺什么>" --body-file request.md
  ```

- **没有 GitHub 账号**:照下面的格式写好,连标题一起贴到 QQ 交流群(群号见仓库 [README](../../README.md#反馈与参与)),群助手会整理成 issue

标题一律以「插件接口需求:」开头,后面一句话说缺什么,比如「插件接口需求:推演插件想按城记数」。

正文的格式(小标题照抄,和网页表单是同一套):

```markdown
### 想做的插件

用一两句大白话说插件要做什么、用的人会看到什么。

### 哪种插件

工具 / 推演 / 地图 / 不确定

### 卡在哪

做到哪一步做不下去了。查过哪几页文档、试过哪个调用、报了什么错或撞了哪条上限。

### 需要的接口

你希望有什么:要读到什么数据(每个地块 / 每州 / 每国 / 每座城 / 每个人一份?哪一年的?)、
要改什么、要在界面上放什么。有想好的写法可以写几行示意的代码,没有也行。

### 结果要不要留在世界里

只在开着插件时显示 / 要存进世界、能跟着世界分享 / 不确定

### 别人没装这个插件时

打开用过它的世界,你希望别人看到什么:和装了一样 / 看得到结果但改不了 / 看不到插件那部分也行。

### 现在的替代做法

没有这个接口时你打算怎么凑合(少做哪一块、拿什么近似)。没有就写「没有」。

### 补充

别的想说的:参照了哪个游戏或工具的哪个功能、有几个人想要、急不急。
```

### 一条写好的需求

> **插件接口需求:推演插件想按城记数**
>
> ### 想做的插件
>
> 「城防」:每座城有一个城防值,和平时慢慢修、被围时往下掉,城防高的城更难打下来。地图上点开一座城能看到它的城防。
>
> ### 哪种插件
>
> 推演
>
> ### 卡在哪
>
> 推演插件自己的表只能按州、按国、按全世界记(sim.md「自己的表」的 `unit`),一州里有好几座城时分不开。影响口里也没有管「这座城好不好打」的。
>
> ### 需要的接口
>
> 1. 表的 `unit` 能写 `settlement`,一座城一格;城毁了那格留着
> 2. 一个按城的影响口,乘在攻城的胜算上
>
> ### 结果要不要留在世界里
>
> 要存进世界:城防跟着历史走。
>
> ### 别人没装这个插件时
>
> 历史照常能看(哪座城哪年被打下来已经在历史里)。城防那个数看不到也行,能看到更好。
>
> ### 现在的替代做法
>
> 按州记一个城防,交给 `war.power` 乘到整个国上。一州只当有一座城,而且守方全国都变强了,不对。
>
> ### 补充
>
> 没有。

## 写的时候

- **一条只提一件事。** 两样不相干的接口分两条提,各排各的
- **先说用途,再说接口。** 只写「要一个 `xxx()` 调用」很难判断该怎么给;写清想做的插件,有时现有接口换个用法就够,回复里会告诉你
- **别贴私人的东西。** issue 谁都能看:不贴密钥、账号、世界里不想公开的内容。发现安全漏洞不走这里,见 [CONTRIBUTING](../../CONTRIBUTING.md#安全问题)
- **让 AI 起草的,发之前自己读一遍。** 确认它写的就是你想要的

## 提了以后

- 需求会定期汇总,同一件事的并到一起看。附议的人多、说得清用途的排得靠前
- 接口只加不改:新接口加进来,老插件不用动。加了会写进这几页文档和版本的更新说明
- 不是每条都会做,也不承诺时间。有的会给一个换种做法就能做到的回复;做不了的会在那条 issue 里说原因

## 给 AI 助手

你在帮人写「文明与地图」的插件。想做的事接口里没有时:

1. **停下来说清楚。** 告诉用的人「这一步现有接口做不到」,缺的是哪一样:读不到什么、改不了什么、撞了哪条上限。不要不声不响换成别的做法
2. **不要编。** 只用这几页文档和类型定义(`civ-atlas.d.ts`、`civ-atlas-sim.d.ts`、`civ-atlas-map.d.ts`)里有的调用、能力、口子、命令。不要拿别的数据凑一个看起来差不多的结果,也不要假装做成了
3. **不要绕。** 联网、`eval`、直接 `postMessage`、另开线程这些都被沙箱拦着,试了插件会被停掉
4. **可以提退一步的做法。** 少做一块、拿别的数近似都行,但要说明和原本想要的差在哪,由用的人决定用不用
5. **把做得到的部分做完。**
6. **起草一条接口需求。** 先搜有没有人提过:

   ```bash
   gh issue list --repo guaner-334/civ-atlas --state all --search "插件接口需求 <关键词>"
   ```

   有同一件事的,把链接给用的人,建议去附议。没有的,照上面[怎么提](#怎么提)的格式写成 `request.md`,给用的人看
7. **用的人点头了再发。** issue 是公开的、用的是他的账号。他同意、`gh` 也登录了,可以替他提(命令见上);没登录就把标题和正文交给他,请他贴到网页或 QQ 交流群
8. **同一个缺口只提一次,一条只写一件事。** 不写用的人的密钥、账号、私人内容
