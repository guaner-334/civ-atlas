# 插件开发

给会写一点 JavaScript、想给「文明与地图」写插件的人。插件能读地图和历史、算东西,结果交给网站:在侧栏放一张卡片(文字、数字、表格、按钮),在地图上加图层和标注,或者替你改名、加标记、下命令。

> **插件功能还没开放。** 网站上还没有装插件的入口;这份文档照接口第 1 版写,入口开放以后照这里写的用。
> 开放之前接口的细节还可能调整,调整了会改这份文档。

## 插件是什么

一个插件就是一个 `.civplugin` 文件,里面是一份清单、一个 JS 文件、说明和许可证。装上以后:

- **它跑在一个隔开的地方**:网站给每个插件开一个单独的后台线程,线程外面再套一层沙箱。它不能联网,看不到网站的页面、你的 AI 密钥和账号、别的世界,也不能自己改历史。这些不是靠审核,是技术上做不到,见[能力、权限和限制](limits.md)
- **它要什么都得在清单里写明**:读地图、读历史、看你写的东西、加图层……每样叫一个「能力」。装的时候网站把这些翻成大白话列在权限框里,你点了「装上」它才拿得到
- **画东西的是网站**:插件只交数据(每个地块一个数、一串标注、面板上放哪些格子和按钮),长什么样由网站按自己的样式画。所以平面地图、地球、导出图片都自动支持,插件也没法把界面画得像网站自己的提示来骗人
- **网站这边的数据它拿到的都是复制的一份**:插件改了自己手里的数组,世界不变。要改你写的东西(改名、加标记、下命令)只能「提要求」,网站检查过再照办,照办的整批记一步撤销

插件分两种:

- **工具**(清单里 `role` 写 `tool`):在地图上量一量、算一算,或者加一个图层。这一页和[接口参考](api.md)讲的都是工具插件
- **推演**(`role` 写 `sim`):在推演里跑,每隔几年出手一次,交数影响官方的决定、下命令、写编年史、加自己的新数值,推出来的历史进世界。它不在上面说的后台线程里跑,在推演线程里的 QuickJS 里跑,接口也不一样,见[推演插件](sim.md)

## 十分钟写一个插件

下面写一个「海拔图层」:按海拔给陆地上色。

**1. 建一个文件夹**,比如 `my-elevation/`,放四个文件:

```
my-elevation/
├── plugin.json   清单里你自己写的那几项
├── main.js       插件代码
├── README.md     说明(装的时候给人看)
└── LICENSE       许可证全文
```

**2. 写 `plugin.json`:**

```json
{
  "id": "my-elevation",
  "name": "海拔图层",
  "version": "1.0.0",
  "role": "tool",
  "api": 1,
  "runtime": "worker",
  "requires": ["world.read@1", "layer.cells@1"],
  "why": { "world.read@1": "要读每个地块的海拔" },
  "description": "按海拔给陆地上色。",
  "license": "MIT",
  "author": { "name": "你的名字" }
}
```

每个字段的意思见[插件包](package.md)。`requires` 里只写用得到的能力:权限框上会一条条列给装的人看。

**3. 写 `main.js`:**

```js
(async () => {
  const world = await civAtlas.world.info();
  const { elevation, water } = await civAtlas.world.cells({ fields: ['elevation', 'water'] });

  // 每个地块交一个数;水上交 NaN,不画
  const values = new Float32Array(world.cells);
  for (let i = 0; i < world.cells; i++) values[i] = water[i] === 0 ? elevation[i] : NaN;

  await civAtlas.layer.cells({
    id: 'elevation',
    title: '海拔',
    values,
    ramp: { colors: ['#1a9850', '#fee08b', '#d73027', '#ffffff'], min: 0, max: 4000 },
    legend: '米',
  });
})();
```

插件拿到的全局对象叫 `civAtlas`,每个调用都返回 Promise。调用名、参数、返回什么见[接口参考](api.md)。

**4. 写 `README.md` 和 `LICENSE`。** README 当纯文字显示,写清插件做什么、为什么要那些能力;LICENSE 放许可证全文(见[许可证](package.md#许可证))。

**5. 打包。** 需要这个仓库的代码和 Node 22 以上:

```bash
pnpm install
npx tsx scripts/pack-plugin.ts path/to/my-elevation     # 写出 path/to/my-elevation/my-elevation.civplugin
```

打包时照网站读插件的规矩核对一遍,哪里不对会直接说。打出来的文件就是插件本身,别拆开重新压缩:网站认插件靠整个文件的指纹。

**6. 装来试**,见下一节。

### 编辑器提示

接口的类型定义在 [`src/plugin/types.ts`](../../src/plugin/types.ts)。在这个仓库里打开 `examples/plugins/` 下的文件,编辑器(VS Code 等)会照 [`examples/plugins/tsconfig.json`](../../examples/plugins/tsconfig.json) 和 [`civ-atlas.d.ts`](../../examples/plugins/civ-atlas.d.ts) 给出 `civAtlas` 的补全和类型检查。在别处写插件,把这两个文件和 `types.ts` 拷过去、改一下里面的路径就行。

## 装来试

入口开放以后:

1. 地图上打开「更多」菜单 →「插件」,打开插件页
2. 点「从文件装…」,选你打出来的 `.civplugin`
3. 网站先检查文件(坏了、要新版网站的会直接说哪里不对),再弹权限框:插件要的每样能力一行,下面是你在清单 `why` 里写的理由
4. 点「装上」。自己打的插件没在作品墙上审过,权限框上会多一条醒目的提示,按钮是「仍然装上」

装好以后:

- 工具在地图右下的「工具」里(手机在右上那一竖排的拼图),点一下开始用:点开才开这个插件,顶层代码从头跑;关掉插件卡就停了。清单里要了 `ui.panel@1` 或 `input.pick@1` 的才出现在「工具」里,只交图层的在图层面板
- 插件交来的地块图层在图层面板的「插件图层」里开关,只交图层的插件也在那里点开;标注图层(路线、框、点)交来就画在地图上
- 图例上点「存进这个世界」,这个地块图层那一刻的样子就存进了世界:别人没装插件也看得到,能跟着世界分享;不想要了点「已存在这个世界里」→「从这个世界里拿掉」
- 插件装在这个浏览器里,所有世界都能用;不自动更新,改了代码重新打包、再从文件装一次就换成新的

### 开发者模式

改了代码不用每次都装一遍:

1. 插件页最下面打开「开发者模式」(记在这个浏览器里),「从文件装…」下面多一个「载入正在写的插件…」
2. 点它,选你打出来的 `.civplugin`。第一次和装的时候一样先弹权限框;同意以后插件页收起,插件对着地图上打开的世界跑起来,地图左下角多一块小卡:「开发中」、插件名和第几版
3. 改完代码重新打包,点小卡上的「重新载入」:停掉正在跑的那个,读新文件再开。要的能力比上次同意的多了才再弹权限框
   - Chrome、Edge 记得你选的文件,点「重新载入」直接再读;Safari、火狐要再选一次文件(浏览器只许这样)
4. 小卡第二行是最近一次载入的时刻和插件代码顶层跑了多久;下面是日志,最近一次载入的排在最上面:

   | 一行写着 | 是什么 |
   |---|---|
   | 信息 | `civAtlas.log` 写的 |
   | 警告 | 哪个调用没成、为什么(`layer.cells 没成：…`);插件照样接着跑 |
   | 出错 | 插件出错停下了的那句话、代码里没接住的 Promise 出错、文件坏了 |
   | 网站 | 插件停下了、照插件的要求改了你写的东西 |

   「复制全部」把日志拷成文字,「清空」清掉
5. 点小卡上的 ✕,或者关掉开发者模式,载入的插件就停掉、小卡收起

载入的插件不进插件列表,只在这个网页里跑,只有你自己看得到。它交的图层和装上的插件一样画在地图上(图例上标「开发中」,不能存进世界);要了面板或点选的,侧栏里和「工具」里开的一样出插件卡、请你在地图上点,卡上「再试一次」就是重新载入。它用 `store.local`、`store.world` 存的东西只放在内存里:重新载入以后还在,刷新网页就没了。

**推演插件**(`role` 是 `sim`)载入以后不跑起来,小卡上多一个「试推 300 年」:在后台用地图上这个世界的地图、种子、规则和干预,带着它选的推演插件(你载入的这个换掉同一个插件,它没选的加在最后),从第 0 年推 300 年。地图上的世界不变。推完小卡上列:

- 每个插件出手几回、一共用了多久、最慢的一回合多久、在哪年
- 照办了几条命令(每种几条)、写了几句编年史
- 分段推:推到第 150 年存下、另装一份插件接着推,和一口气推的一样不一样。不一样多半是插件拿全局变量记了东西(存进世界的只有表、小本子这些,全局变量接着推时就没了),这一行变红,写从哪年起对不上
- 日志按年份:插件里 `console.log`、`console.info`、`console.debug` 记成「信息」,`console.warn` 记成「警告」,`console.error` 记成「出错」;被你的干预挡下的命令网站记一条(「宣战没办：你下了「不许扩张」」);推不下去的那句错在最后

改了代码:重新打包 →「重新载入」→「试推 300 年」。

## 常见问题

**插件能联网吗?能调用 AI 吗?**
不能。插件所在的沙箱技术上连不了任何网址,网站的 AI 也不给插件用,不会花任何人的额度。

**插件算出来的东西存在哪?**
工具算的结果(面板、图层)只在用它的时候显示,关掉就没了,世界一个字节不变。地块图层可以由用的人点「存进这个世界」留下(网站认得的格式,能分享)。插件自己要长期留下东西,可以用 `store.local`(插件自己的设置,不在世界里)、`store.world`(存进这个世界,存了以后世界不能公开分享),或者提要求让网站改「你写的东西」(加个标记、改个名字,和你自己改的一样能分享、能撤销)。

**我的插件改坏了别人的世界怎么办?**
插件改你写的东西都要经过 `author.apply`:网站只检查改完的世界还能存、能打开,不替用的人判断改得对不对;照办的整批记一步撤销,用的人点「撤销」就回去了。

**别人没装我的插件,打开用过它的世界会怎样?**
只看不存的工具不进世界,对别人没有影响。插件提要求改的名字、加的标记、下的命令进了用的人自己的修改,没装插件也照样在。用的人存进世界的地块图层,没装插件也照常看得到(图层面板「插件图层」里)。插件用 `store.world` 存的数据原样留着,别人打开时顶上会说一句用到了没装的插件,装上同一个插件(版本不一样也行)就接着用得上。

**插件能改地形、改推演规则吗?**
不能。推演插件能在推演里加自己的数、在官方留的几个口子上交数(城能长多大、哪国更爱打仗……)、下命令(宣战、结盟、立约……),规则本身改不了,见[推演插件](sim.md)。
